# PixelWeave · 全面审查与工程优化报告

**版本：** Audit 2026-10-25 · Editor / Animation Atlas / Local LLM / Security / Performance / UX  
**边界：** 没有生成或抠取任何图片；**Vermilion Nocturne 仍是唯一正式展出作品**；第三方参考不进入原创作品库，也不用于模型训练。  
**审查方式：** 逐一查看仓库核心模块与测试，研究成熟工具公开的一手设计原则，实施可验证的修复，核对 GitHub Actions 自动测试与部署。**尚未经过真人交互和跨浏览器截图测试。**

## 1. 参考体系：学工作流，不复制别人的界面

| 参考项目 | 一手能力证据 | 对 PixelWeave 的适用推论 |
| --- | --- | --- |
| Aseprite | https://www.aseprite.org/docs/animation · https://www.aseprite.org/docs/timeline | 核心对象不是“动画 GIF”，而是 layer × frame 对应的 cel；洋葱皮、帧范围标签、逐帧时长、区间播放是专业制作闭环 |
| Pixelorama | https://github.com/Orama-Interactive/Pixelorama | 重点学习针对像素的高精度画笔与连续帧控制、可定制面板、原项目备份、非破坏性图层；不要无脑添加几十种工具 |
| Piskel | https://www.piskelapp.com/ | 浏览器优先的实时预览与极短制作路径；明确 GIF / PNG / sprite-sheet 等导出入口，精力先花在画完一件东西 |
| Lospec | https://lospec.com/palette-list | 配色是能检索、说明来源、控制数量和复用的系统，不只是 32 个颜色按钮 |

**重要产品判断：** PixelWeave 不应试图用一个静态站直接取代 Aseprite，而应成为**“文本 LLM 原生像素创作 → 人工逐层评审/编辑 → 真实可导出的动画项目”**的专用工具。参考档案室负责学习；Studio 负责创作；Gallery 只收获认可作品。

## 3. 本轮已实施的工程修复

### P0 / 保存与安全

- **修复存档“写了却没读”**：项目早已有 `persist()` 与 `restore()`，但正式药瓶载入流程没有调用恢复。现在先初始化官方原生药瓶，再恢复浏览器保存的用户编辑和本地项目；禁止旧 `potion-v3` / 未认可 demo 被悄悄复活。
- **硬化本地 LLM 代理请求边界**：只接受 `127.0.0.1:4173` 或 `localhost:4173` 的有效 Host，检查 Origin 和 Fetch Metadata，拒绝跨站或类型错误的 POST；仍监听 127.0.0.1。
- **阻止本地静态服务泄露敏感文件**：禁止 `.env`、`.git`、`node_modules`、`tests`、`dev-server.mjs` 等私有开发内容通过 Web 预览公开读取。

### P1 / 动画画面与导出

- **修复斜向图层展开每帧重复画所有底层像素**：缓存每个图层/帧的原生像素位图（严格以调色板、偏移和像素内容组成缓存键），选中层变化不会触发像素重新生成，修改任意像素则使对应缓存失效；缓存限制 180 项。
- **离屏暂停渲染**：不在视野内时不再逐帧绘制大型斜向展开及选层观察区域；滚动回来再同步更新。使用 IntersectionObserver，兼顾不支持时的回退。
- **最大展开距离不裁切**：按实际图层数量和间距动态扩展展示画布，最后的图层保持可见和可点击。
- **选中图层自动聚焦的取景坐标严格限制在画布内**。
- **增加上一帧洋葱皮**：非破坏性透明叠加前一帧，只在暂停时显示，支持 O 快捷键与缩放同步，不改变工程和 PNG 导出结果。
- **修复画笔默认颜色未包含在当前作品调色板的问题**；选颜色后的按钮语义状态同步；缩放网格步长跟随像素整数倍率。

### P1 / 外部素材研究可靠性

- **本地导入可重新进行帧差分析**：外站图片可能使 Canvas 变为 tainted，原来即使换成本地 PNG 也无法读取像素；现在加载经用户选择的本地文件时重设 canvas backing bitmap。
- **防止异步外站加载抢占本地导入**：每次参考加载采用序列号，后返回的旧请求不能覆盖新选中的研究素材。
- **修复大尺寸本地精灵表的越界剪裁**：必要时采用适合可用窗口的缩小比例，而不是强制 1x 导致画面被裁。
- 保留并明确外站防盗链、失效或缺少 CORS 的限制，不绕过作者网站限制。

## 4. 核心架构缺口（尚未完成）

| 紧迫度 | 缺口 | 下一步应交付的验收标准 |
| --- | --- | --- |
| **P0** | **真正的 cel 时间轴** | 图层 × 帧构成二维网格；可直接选中并编辑单元格、复制/移动/复用帧；至少 2 个真实项目回归演练 |
| **P0** | **存档恢复端到端证明** | 实测绘制→刷新→恢复、撤销→重做→导出→导入，防止新旧版本存档兼容缺陷 |
| **P1** | **基础画像素工具** | 直线、矩形、填充、选区与移动；保证 1x 可控和连续笔画的单次撤销 |
| **P1** | **循环与时序模型** | 每帧持续时间、loop / ping-pong / reverse、帧范围标签，且导出与预览保持一致 |
| **P1** | **艺术品质检查** | 可解释的 silhouette / color cluster / material / frame seam QA，设人工审美 Gate，不能用颜色数量代替品质 |
| **P1** | **浏览器集成测试** | Chrome/Firefox 交互 smoke、移动端主工作流和 15 分钟动画预览，记录真实卡顿与内存 |
| **P1** | **参考库原站质量** | 对每条链接做人工/自动可达性核验，并区分“可播放原帧”“仅目录索引”和 CORS 可用性 |
| **P2** | **格式与组件归一** | 将旧 Demo / legacy matrix 从正式 runtime 的逻辑分离到 archive 或适配层；UI 样式以一个 design system 为准 |
| **P2** | **专业导出** | GIF / APNG、帧尺寸/方向自定义、多序列和裁切策略，附透明度一致性测试 |

**特别注意**：渲染性能优化没有得到 Chrome 性能分析数字，只能称为“消除了算法上的冗余”；不能编造提升百分比。

## 5. 下一阶段建议（不要再随意增加功能）

1. **编辑闭环 Sprint**：先实现 cel grid + 正确选择帧/图层 + 连续笔画一次撤销 + 存档恢复集成演练。这个优先级高于额外海报效果。
2. **动画制作 Sprint**：补关键帧时长、循环模式与非破坏性动态观察，让药瓶完成从制作到验证再到导出的全过程。
3. **质量与交付 Sprint**：建立真实模型 A/B 和跨浏览器测试，手工审美 Gate 未过不添加第二件素材。

## 6. 测试边界与参考代码

- 新增 `src/local-request-guard.mjs` 和 `tests/audit-hardening.test.mjs`：主机/来源限制、静态私密文件防护、存档初始化、洋葱皮与图层缓存回归。
- 核心修复分别位于 `dev-server.mjs`、`src/main.js`、`src/exploded.js`、`src/layer-focus.js`、`references/reference.js`，均保留文本原生像素数据。
- Actions `npm test` 和 `deploy-pages` 用来核对每次提交；报告中的测试数量以最新 CI 的实数为准。
- **未进行**：在真实浏览器中进行手动操作/录屏评测、外站每个图片的实际加载监测、本地真实第三方文本 LLM 生成基准、审美打分背书。

## 7. 完成定义

PixelWeave 不应把“功能按钮变多”当成功。真正的标准是：用户从打开页面开始，能够无歧义地找到素材 → 正确编辑具体 cel → 调整动画 → 可靠保存与恢复 → 用原生分辨率导出 → 对照参考反思画面。每一环缺失都应记录，不再以漂亮概念图掩盖工程问题。
