## 0. 阅读须知

**像素艺术不是“把画面缩小再放大”。** 创作者有意识地控制离散像素、像素簇、边缘节奏、有限色板、负空间和可读性，才构成其独特的视觉语言。关于定义及典型误区，请先读 [Lospec 入门](https://lospec.com/articles/pixel-art-where-to-start/) 和 [Pixel Joint 的系统教程](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)。

本书的目标分为三个层次：

- **人类理解**：读懂专业像素画师为什么这样处理画面；能在工作站上检查和局部修正。
- **模型执行**：让文本 LLM 在固定场景描述、规则和约束下逐层创作，不把未经验证的猜测当知识。
- **系统验证**：PixelWeave 检查尺寸、色板、行宽、帧数、图层数据、运动与循环；主观美感交由人工与视觉评估，并不断复审。

**重要区分**：文中标注的“建议值”（例如 16×16、8–12 色、4–8 帧）是课程练习和初期 LLM 生成的**默认起点**，不是所有像素美术都必须遵守的物理法则。艺术风格允许有意识突破规则。硬性数据约束与审美启发式必须分离。

**资料合规**：所有教学解释、示例任务与规范均为独立整理；只保存外部公开课程的链接和简短摘要，不复制第三方教程的整篇文字、配图、精灵表或付费内容。素材授权与转载条件需另行核对。

## 2. 全课程贯穿的 12 条原则

1. **先理解主题和观看尺寸**，明确是游戏道具、角色表情，还是横版背景。
2. **先轮廓后细节**：在 1× 原尺寸与单色模式下必须可读。
3. **优先大形体，再到中型像素簇，最后才是个别高光像素**。
4. **一块像素承担具体功能**：表达形体、材质、光影、运动或情绪；无意义噪点尽量删掉。
5. **控制线条节奏**：避免不规则台阶、轮廓锯齿和不必要的 double pixels。
6. **明暗随体积和光源转折**：谨慎使用围绕整个边缘等距加亮的 pillow shading。
7. **色板要有角色分工**：轮廓/暗部/中间色/主光/极亮点，不能靠无限新增颜色补救形体。
8. **材质靠选择性信息区别**：金属硬反光、玻璃透射边缘、液体宽色块、木材顺纹理。
9. **层与时间线要解耦**：静止的瓶塞不因液体动而重绘跳变。
10. **动画先关键姿态和体积，再局部粒子**：避免全物体无理由漂浮或闪烁。
11. **循环验证最后一帧到第一帧**，不是仅检查逐帧顺序。
12. **每次改动都让艺术判断可追踪**，保存版本和局部差异以便回退。

原则来源综合：[Pixel Joint](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)、[Derek Yu](https://derekyu.com/makegames/pixelart.html)、[Slynyrd 教程目录](https://www.slynyrd.com/pixelblog-catalogue)、[Saint11 教程库](https://saint11.org/blog/pixel-art-tutorials/)；此处为本项目自拟的教学原则，不是引用来源的原文清单。

## 4. 如何学习一章

每章统一要求：

1. **定义**：区分术语、目的与使用范围。
2. **观察**：先在来源教程中找正反例，描述画师的决策，而非抄具体图像。
3. **练习**：在限制画布、色彩和帧数条件下制作原创素材。
4. **评价**：原尺寸辨识、放大像素簇、灰度结构、帧间稳定、循环断点。
5. **复盘**：指出失败属于形体/色板/材质/运动/输出格式哪一层，**只重修对应层**。

入门不要先做 1920×1080 的壁纸。先用 16×16 静态物品证明轮廓表达力，再用 24×24 的瓶子证明材质，再用四帧证明液体与玻璃可以独立运动。

## 5. 人类工作站应提供的检查模式

| 模式 | 目的 | 通过依据 |
| --- | --- | --- |
| 1× 原尺寸预览 | 判断真实观看距离是否可读 | 无需放大能区分物体类型 |
| 黑色剪影 / 灰度 | 测试形体与明度分组 | 亮暗关系清楚，主物体不消失 |
| 调色板视图 | 发现无用途的近似色 | 颜色各自有可解释的角色 |
| 单图层隔离 | 检查层内像素簇、遮挡与边缘 | 图层语义清楚，移除其他层仍能理解作用 |
| Onion skin / 帧差异 | 检查帧间漂移、运动弧和稳定锚点 | 静态结构没有无意义抖动 |
| 首尾跳转 / 循环预览 | 检查循环拼接 | 无明显“跳一下”或突然消失 |
| 参考与版本对比 | 审美迭代 | 能具体说出为何更好，而不是只说“更精致” |

这里的 onion skin、图层、cel、时间线等属于行业常见工作流，参考 [Aseprite 官方入门](https://aseprite.org/docs/basics/) 与 [Onion Skin 文档](https://www.aseprite.org/docs/onion-skinning/)。

## 6. 适用于 PixelWeave 的最小创作路线

**第一件目标作品：一瓶可以逐层编辑的生命药水。**

- 分辨率：建议先 24×24 或 32×32，而不是一上来 64×64。
- 稳定层：瓶塞、瓶身轮廓、玻璃底色与固定阴影。
- 动态层：液面、液内亮区、气泡和偶发闪光。
- 关键挑战：液体仅在玻璃内部变化；瓶塞和外轮廓保持一致；亮点不满屏乱闪。
- 发布门槛：单帧美观、逐帧连贯、循环平顺、导出可重现、JSON 可回读。

详见 [03 道具设计](03-ASSET-DESIGN.md)、[04 动画原理](04-ANIMATION.md) 与 [10 训练计划](10-CURRICULUM.md) 的完整血瓶练习。

# L0 · 像素的基本语法：从点到可信的轮廓

**配套原创视觉实验：[轮廓台阶、像素簇与逐像素修订](labs/01-PIXEL-CLUSTERS.md)**。先跟练正反例，再完成本文知识点。

**目标**：让每一枚像素参与描绘形体，而非简单制造马赛克。完成本章后，应能只用 2–4 色做出原尺寸可辨的 16×16 小物件。

## 1. 像素艺术与像素化滤镜的区别

像素化处理通过采样/降分辨率降低信息密度，未必有设计过的边缘与像素簇。像素艺术则主动在离散网格上选择保留或删去信息。鉴别时问：
- 主体轮廓是否在原尺寸仍可理解？
- 每段阶梯线条是否在服务曲线，而非随机震荡？
- 不同色块的边界有没有解释体积与受光？
- 是否有不承担任何功能的孤立噪点？

参考：[Lospec, Pixel Art: Where to Start](https://lospec.com/articles/pixel-art-where-to-start/)。

## 2. 基本画布与像素比例

初学建议先用 16×16、24×24、32×32，从小到大增加。先在整数网格作画；预览放大采用 nearest-neighbor，不要无意使用线性模糊。游戏和壁纸可以在设计好的逻辑低分辨率画布渲染，最终按整数倍或清楚定义的缩放规则展示。不要在同一场景中意外混用 1px、2px、4px 的笔触比例。

练习：在 16×16 的空白画布上，用一种黑色画出钥匙、苹果、瓶子。缩到原尺寸后，让另一人不看题目识别 3 个物体。识别失败先修剪影，不加纹理。

## 3. 线条与像素阶梯

直线、斜线、圆弧由水平/垂直/斜向台阶排列。平滑的斜边往往有稳定的台阶节奏，避免不规则的长短跳变和相邻方向反复改变。短台阶不是绝对错误；它可以表现转折，但必须是故意的。

**常见问题**
- jaggies：曲线上局部凸凹、不协调的台阶导致边缘在视觉上“刺”。
- double pixels：不合理的并列双像素改变了线宽，显得脏或粗。
- broken contours：轮廓在本应闭合处断裂，造成材质溢出或不稳。

修复方法：切换单色显示→放大 8× 检查台阶→在原尺寸复核。仅修轮廓，不同时补颜色。

参考：[Pixel Joint 综合教程](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)。

## 4. Pixel Cluster 像素簇

像素簇是视觉上连续的一组同色/近似同功能像素块，承担明暗面、边缘、纹理或结构信息。好的像素簇能用少量形状传达体积；细碎的 1px 孤点往往容易产生“盐和胡椒”般的噪声。

从大到小规划三种信息层：
1. 大像素簇：主体、外轮廓、主要明暗面。
2. 中像素簇：结构连接、材质形状、焦点高光。
3. 微像素：少量关键闪光、眼睛或边缘修正。

不要把“孤立像素必定不好”写成程序硬规则：星点、眼睛、火花可以理直气壮地是孤点。关键是它是否有目的、是否破坏阅读。

参考：[Pixel Joint 教程](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)；[Slynyrd, Back to Basics](https://www.slynyrd.com/pixelblog-catalogue)。

## 5. 负空间与视觉层级

剪影不是越填满越好。瓶把手中间的空洞、角色手臂和身体之间的三角空间、提灯支架间隙都是重要的可读信息。尝试在不加颜色的情况下用负空间区分物件部件。

**训练方案**：制作三个版本：A 纯黑剪影，B 轮廓+底色，C 加两级明暗。若 C 可读但 A 完全不可读，要么形体过度依赖颜色，要么题材确实需要内部结构。前者应修；后者记录例外。

## 6. AA、Sel-out、Banding、Pillow Shading 入门

- **Anti-aliasing（AA）**：用中间色减缓锯齿，适当时有效；过度会模糊质感。新手先不用 AA 熟悉线条节奏。
- **Banding**：平行相贴、连带重复的窄色带可能使形体出现尴尬条纹。不能简单通过“检测平行像素”断定不佳。
- **Pillow shading**：无视真实体积/光向，机械地从四周深到中心亮。除特定风格外通常削弱立体感。
- **Sel-out**：选择性描边的一种特定历史术语，在不同像素流派中评价不一；优先按对比与轮廓阅读判断，不要一刀切禁用。

详细解释与图例查看：[Pixel Joint Tutorial](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)。

## 7. L0 结业任务与门槛

**交付**：16×16 透明背景钥匙、血瓶、灯笼各一个，最多四种实际颜色；提供原尺寸 PNG、8× 放大图与色板表。

**通过**：轮廓闭合；没有明显无意的外轮廓凸刺；原尺寸易于辨识；每一块色彩有明确用途。**失败时只返工轮廓/负空间**，不允许通过增加纹理掩饰。

**模型调用**：只加载本章“剪影/像素簇/线条”+ 核心资产 Schema，先生成 1 帧 1 层剪影；通过后再进下一层。禁止直接生成 12 帧复杂动画。

# L0 实验：像素簇与轮廓的逐像素修订

来源：Pixel Joint / cure 综合教程：https://pixeljoint.com/forum/forum_posts.asp?TID=11299 。本实验示意及练习均为 PixelWeave 原创，不复制原教程图片。

## 对照 1：轮廓台阶

![原创轮廓错误/修正对照](../visuals/01-contour.svg)

**流程：**
1. 在 Studio 隐藏填充/高光，只看单色轮廓，1× 观察大形。
2. 放大 8×，寻找不符合目标曲线的突然跳步，记录 (x,y)。
3. 先“移动”而不是“补满”：原位置去掉一个像素，在目标边上补一个像素。
4. 检查负空间是否因修复变窄或闭合；再缩回原尺寸。
5. 两份工程保留 before/after，记录调整坐标及原因。

不等长台阶不一定错误。岩石、荆棘和破损刀锋可能需要突然转折；检查意图，而不是仅统计转角。

## 对照 2：像素簇还是散点噪声？

![原创散点/受光像素簇对照](../visuals/02-clusters.svg)

1. 将主物体分成暗面、主色、亮面三个连续块。
2. 隐藏全部微高光；把 5–10 个随机单像素亮点重新组织成 1–2 个受光面。
3. 返回 1× 看体积。原尺寸更清楚时才继续细化。
4. 眼睛、火花、星点允许独立像素：孤点不是绝对错误，必须有语义。

## 可编辑的完整练习

[下载原创钥匙工程](../examples/reference/readable-key.layered.json)。Studio → 导入 JSON → 分别隔离 contour / fill / glint 三层。

- 仅显示 contour：柄部孔洞必须看得出。
- 显示 fill：检查杆身明暗是否沿一致方向。
- 显示 glint：高光必须辅助金属阅读，而不是破坏剪影。
- 故意在钥匙柄边缘画一枚突刺，再用单像素移动修复，导出两个 JSON 版本。
- 找另一人不看文件名识别图案；不要把模型自评当外部识别测试。

**出口门槛**：1× 可识别、轮廓连续、像素簇有职责、可以给出具体修改坐标、全部帧与图层通过数据校验。

拓展阅读：Slynyrd 基础 https://www.slynyrd.com/blog/2018/5/16/pixelblog-5-back-to-basics 。

# L1 · 色板、光影和材质设计

**配套原创视觉实验：[受光方向、色板聚类、玻璃/金属/水晶](labs/02-MATERIAL-LIGHT.md)**。使用三件可编辑参考资产检验每一步。

**前置**：[01 基础语法](01-FOUNDATIONS.md)。**结业**：用有限颜色把玻璃、金属、液体区别开。

## 1. 色板不是“颜色越丰富越精致”

建立功能性色板：轮廓暗色 / 受光暗面 / 主基色 / 受光亮面 / 极亮点 / 材质专属色。初学练习 4–8 个实际颜色足够；复杂画面可拓展为 12、16、32 色或更多，取决于风格，不设统一上限。

**色板渐变 Color Ramp**：一个物体从暗部到亮部的若干颜色应形成明度与色相的合理路径；不要只把 RGB 三通道一起加亮。Hue Shift 可让冷暖、光源、情绪更丰富，但也不是强制配方。

参考：[Slynyrd 色板指南](https://www.slynyrd.com/blog/2018/1/10/pixelblog-1-color-palettes)；[Lospec Palette List](https://lospec.com/palette-list/)。

## 2. 先明度，再色相，最后饱和度

一套稳定的工作顺序：
1. 选定画面主光方向与背景明度。
2. 在灰度图上建立清晰的亮/中/暗三大面。
3. 以色相和饱和度区别温度、材质、情绪。
4. 用非常少的极亮点建立画面注意力。
5. 在实际展示背景上检查透明资产；不要只用棋盘格看图。

**禁止把阴影写成“整个物体底部一律加黑”。** 阴影应解释几何形体、接触关系、投影与环境光。多光源可存在，但需要主次关系。

参考：[Slynyrd Light and Shadow](https://www.slynyrd.com/blog/2018/6/15/pixelblog-6-light-and-shadow)；[Derek Yu Pixel Art Basics](https://derekyu.com/makegames/pixelart.html)。

## 3. AA 与 Dithering 的使用边界

AA：用精心选择的中间色柔化局部曲线。低分辨率、硬朗复古设计可无需 AA。处理轮廓时先确定线条节奏，再决定要不要 AA。

Dithering：用特定离散图案在有限调色板下模拟过渡、颗粒或材质。适合硬件风格和有明确媒介感的作品；若对 16×16 小瓶全表面撒棋盘噪点，反而会毁掉像素簇。

Ditherpunk 是一个可以选择的特定艺术方向（高对比、抖动图案和复古视觉表达），**不是像素动画的默认风格**。风格标签必须跟构图、美术角色一致。

阅读：[Pixel Joint 对 AA/抖动/噪点的讨论](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)；[Slynyrd Texture](https://www.slynyrd.com/blog/2018/2/15/pixelblog-2-texture)。

## 4. 四种材质的“识别特征”

### 玻璃 Glass

玻璃由外缘、局部折射/透射、高反差窄反光以及“能看到瓶内物体”共同表达。不要把全部瓶壁涂成不透明的白框；瓶壁厚度在转角处可用像素簇强调。试验时先建立稳定玻璃层，动态液体另立一层。

### 液体 Liquid

液面与容器壁有联系；液体体积受容器形状约束。主色块连续，液面高光可断续而非每像素均闪。气泡频率和尺寸应与液体环境一致。参考 [Slynyrd 水体动画](https://www.slynyrd.com/blog/2018/10/12/pixelblog-10-water-in-motion)。

### 金属 Metal

需要相对硬、窄、高反差的反光，亮暗面突变比木头/布料更鲜明。金属表现重点是切面结构及映照光源，不是均匀铺大量黄点。

### 木材/石材/织物

木头纹理顺结构，石材依大块断面与碎裂，布料靠褶皱方向与厚度变化。纹理分布要服务受光、形体和视觉重点。**纹理要从抽象形状构成，而不是噪点铺满**。

阅读：[Slynyrd Texture](https://www.slynyrd.com/blog/2018/2/15/pixelblog-2-texture)；[Saint11 主题教程索引](https://saint11.org/blog/pixel-art-tutorials/)。

## 5. Texture：重复不等于机械平铺

训练时画出 2–4 种典型微结构：石头凹口、树皮竖纹、砖缝、金属反光。但要调节疏密、方向、聚散，使焦点区域更明确。材质信息应服从物体大形体。可以用程序化纹理生成初稿，**最终需按像素簇逻辑清理**。

## 6. 光照一体化检查清单

- 主光位置明确；材质反光与该光源相符。
- 投影方向与接触位置匹配；没有无故漂浮。
- 角色/道具/背景色板共享环境色的逻辑。
- 高光面积远小于主体面积，除非有意设计强发光物。
- 发光物是“光源 + 被照亮的邻近表面”，不是只有自身发白。
- 暗部仍保留关键结构，不是一团纯黑无信息。

## 7. L1 结业：三件静态资产

**24×24 或 32×32，建议 8–12 个实际颜色**：
- 玻璃血瓶：表现瓶壁、内部药液与瓶塞。
- 黄铜提灯：表现金属反光和玻璃罩。
- 裂纹魔晶：表现切面、半透明层次及主发光面。

提供三件资产的：彩色版、黑白版、灰度版、调色板表、光源示意。人工能在原尺寸看出三种材质差异才通过。

**模型分工**：先定 palette 与光向，再分玻璃/主体/高光图层；高光层不得推翻经过审核的剪影。失败时返回具体“材质识别失败”的区域，而不是要求“整体更精美”。

# L1 实验：方向光、受光面、材质差异

来源：Slynyrd 色板、光影和纹理专题；Pixel Joint pillow shading / dithering 技法。所有对比图为 PixelWeave 自制示意，非作者原图。

## 光照示意

![原创枕头式明暗与方向光对比](../visuals/03-lighting.svg)

所谓 pillow shading 的常见问题不是中间亮色本身，而是没有光源或形体解释，机械沿边缘一圈圈变亮。

- 步骤 1：在旁边写明主光位于左上，别让模型自行改变光源。
- 步骤 2：只用暗部 / 中间色 / 亮部三种明度组画形体；不要提前加纹理。
- 步骤 3：放大检查受光面是否遵从形体的朝向。
- 步骤 4：灰度 1× 检查主次；再决定是否做 Hue Shifting（明暗色相变化）。
- 例外：中央发光的魔晶或正面打光的人像，中心亮是合理的。

## 材质：抖动不是万能精致滤镜

![原创噪点式抖动与有方向纹理对照](../visuals/04-texture.svg)

从 1× 看是否因为细碎色点丢失了体积。Dithering 可用于特定复古风格，不能仅因为某种“反噪声”规范就全部禁用，也不能缺少设计意图而覆盖整个物体。

## 三件可编辑对照素材

| 素材 | 单独检查的层 | 应形成的效果 |
| --- | --- | --- |
| [玻璃药水](../examples/reference/scarlet-vial.layered.json) | glass / reflections / liquid | 玻璃边缘、液体内部与反光相互独立 |
| [黄铜提灯](../examples/reference/hearth-lantern.layered.json) | frame / highlights / flame | 固定金属框架，局部受光解释灯火 |
| [多面晶体](../examples/reference/prism-crystal.layered.json) | shape / facets / shimmer | 每个切面的明暗属于同一形体，闪光只是次级 |

**实作**：各复制一份工程。错误版增加 8–10 个分散亮点；修正版删去无意义亮点，重新以材质受光区域聚类，保持总色数不变。记录三个物体的主光方向和至少一个具体修复区域。

**出口门槛**：隐藏 highlights 后主体可读；玻璃、金属、晶体有不同反光逻辑；只有经过外部观众原尺寸辨识，才可声称“材质识别通过”。

延伸：[色板](https://www.slynyrd.com/blog/2018/1/10/pixelblog-1-color-palettes)、[光影](https://www.slynyrd.com/blog/2018/6/15/pixelblog-6-light-and-shadow)、[纹理](https://www.slynyrd.com/blog/2018/2/15/pixelblog-2-texture)。

# L1 → L2 · 静态道具到分层动画素材：造型先于细节

**案例库：[6 件按材质/动画拆层的原创教学工程](examples/reference/README.md)**。所有作品是代码编排教学样例，未通过外部专家审美评审。

**本章核心**：物品不是几个矩形块的堆叠，而是一套“可读的轮廓、逻辑合理的物理结构、统一的材质、明确的视觉焦点”。

## 1. 道具的创作六步

1. **用途定义**：明确玩家/观众应该在第一眼识别“药水”“提灯”“金币”“钥匙”，还是只需感受“神秘、稀有、危险”。
2. **尺寸与投影确定**：16×16 的背包图标、32×32 的精致道具、64×64 的展示插画的设计重点不同。项目中同类物品必须遵守相似的观看距离与透视习惯。
3. **黑白形体**：提取 3–5 个形体关键点；画至少 3 个剪影方案，挑选最具辨识度的一种。
4. **色块与体积**：通常先背景和外轮廓，再基色、主要暗面、亮面。不要过早做微纹理。
5. **材质特征**：玻璃瓶强调边缘折射、内部内容物；提灯金属结构与火光；水晶强调切面而非随意闪光。
6. **可动结构拆分**：先辨别什么应该完全静止，什么会形变，什么独立循环。动画开始前写好层次规划。

**参考案例**：[Slynyrd Pixelblog 24 Items](https://www.slynyrd.com/blog/2019/12/21/pixelblog-24-items)——对 16×16 小道具、类型辨识和适合不同物件的 Idle 动画尤其有价值。

## 2. 实际血瓶结构规范

**建议逻辑画布**：24×24（入门）或 32×32（细节阶段）。仅为练习基准，非绝对最优规格。

画面由以下内容组成：

| 语义对象 | 是否应独立图层 | 是否逐帧变化 | 风险 |
| --- | --- | --- | --- |
| 瓶塞与封蜡 | 是 | 默认静止 | 瓶口位置每帧漂移 |
| 外轮廓与瓶壁 | 是 | 默认静止 | 侧壁粗细忽大忽小 |
| 容器内部透明底色 | 是或合并玻璃层 | 静止 | 变成不透明色块 |
| 药液体积与液面 | 必须独立 | 缓慢变化 | 药液越出瓶壁或体积随意增减 |
| 气泡 | 建议独立 | 稀疏漂浮 | 位置随机闪现、时间节奏不一致 |
| 反射高光 | 独立 | 大部分保持，少量微动 | 玻璃整个轮廓闪烁 |
| 地面阴影 / 光点 | 按场景选择 | 低频变化 | 没接触点或过度抢焦点 |

## 3. 层次要“按语义分”，不是按颜色分

坏做法：红色层、紫色层、白色层、灰色层。好做法：玻璃轮廓、内部药液、气泡、外部光效、瓶塞。因为真实修改通常是“让药液晃得更慢”“移除环境闪光”，而不是“隐藏所有红色”。

层之间应尽量**少重叠、遮挡顺序明确**。透明玻璃层在液体层前还是后，取决于它要表现的玻璃边界和光泽；可以拆为玻璃基底（后）和玻璃高光（前），避免模型猜测所有权。

## 4. 设计稳定锚点与局部重绘边界

每个资产先确定 stableAnchors（逻辑概念，当前 DSL 尚未全部实现）：瓶底接触线、瓶口中心、瓶身最宽两侧、整体重心。LLM 每次修改某一动态图层时，所有稳定锚点的图像坐标保持不变。

建议未来采用 layerPatch 操作而非“重生整张图”：指定 layerId、frameIndices、bbox、allowedSymbols，只允许改变目标范围。这可大幅降低所谓“美术提升”却导致角色/服设漂移的问题。

## 5. 小资产设计通用模板

**Brief**：名称、物体用途、情绪氛围、投影方式、逻辑分辨率、观看背景、受光方向、材质主次。

**Shape Sheet**：3 个单色剪影变体与选择理由。

**Palette Sheet**：轮廓/暗部/基色/亮面/极亮点，用语义而不是单纯编号命名颜色。

**Layer Plan**：按顺序列出每层：id、语义、遮挡、能否动画、稳定锚点。

**Review**：在 1× 原尺寸、灰度、透明棋盘、深浅背景下分别检查。

## 6. 道具动画不应千篇一律

某些游戏道具以浮动展示，某些以落地弹跳，某些仅发亮。液体瓶不一定整瓶浮动；提灯可能只有火焰跳动；金属钥匙不应因为“动画要显眼”而每帧都变形。让动态逻辑服从物理关系和叙事意图。

来源：[Slynyrd Items](https://www.slynyrd.com/blog/2019/12/21/pixelblog-24-items)。

## 7. 交付与质检

输出：一件 32×32 的分层血瓶静态主帧，附上图层职责表、稳定锚点、色板说明。与完成的动画任务独立验收。

**合格条件**：独立隐藏任何动态层都不破坏玻璃主体；所有可动部分有清楚边界；无材质穿帮；层名可让不知情的人直接理解。**失败优先改层次结构与剪影**，不要先开始动画。

# L2 · 从静态像素到可信动画

**配套实践：[血瓶液面 8 帧、火焰与旗帜](labs/03-ANIMATION-CYCLES.md)**。学习逐帧坐标和循环事件生命周期。

**前置**：[L0 轮廓](01-FOUNDATIONS.md)、[L1 材质](02-COLOR-LIGHT-MATERIAL.md) 与 [分层道具](03-ASSET-DESIGN.md)。

## 1. Animation = 形体 × 时间 × 变化逻辑

动画不是把几张几乎无关的图片快速播放，而是同一个物体在时间轴上持续改变状态。需要同时控制：

- **位置**：移动弧线、速度、加速减速；
- **形体**：外轮廓、挤压拉伸、受力变形；
- **材质**：亮面随形体或光源变化；
- **连续性**：不参与运动的结构在帧间保持一致；
- **节奏**：持帧（hold）、快慢变化、停顿与强调；
- **循环**：末状态与开头运动逻辑无缝连接。

参考：[Slynyrd Intro to Animation](https://www.slynyrd.com/blog/2018/8/19/pixelblog-8-intro-to-animation)、[Aseprite Animation](https://www.aseprite.org/docs/animation)、[Saint11 动画主题教程](https://saint11.org/blog/pixel-art-tutorials/)。

## 2. 区分帧数、FPS 与每帧时长

F = 帧数、FPS = 播放时的每秒帧率，则匀速播放周期 T = F / FPS。例如 8 帧、8 FPS → 1 秒。现实项目会使用不同帧持时：例如强调帧保持 150–250 ms，过渡帧只保持 50–90 ms，以形成富有表现力的节奏。

像素动画**不追求一律 60 FPS**。优秀的 6、8 或 12 FPS 循环可以比 30 FPS 但帧间形体崩坏的动画更自然。具体选择随题材与美术语言变化。

时间轴里“帧 Frame、图层 Layer、图层与帧交叉的 Cel”必须明确；Aseprite 是优秀的工程模型。[官方介绍](https://www.aseprite.org/docs/sprite/)。

## 3. 先关键状态，后中间帧

四帧练习的通用构思：

- F0：平衡态（关键姿态）。
- F1：向目标变化（速度/惯性）。
- F2：极值态（关键姿态）。
- F3：回归（与 F0 接轨）。

但这不应成为严格模板。不同动作具有不同关键时刻；火焰和气泡是非周期随机感，但仍要维持确定性的可循环结构。

**不要**先做全部 4–16 帧，再去想主运动。先在黑白剪影动画上验证“动作是否表达清楚”。

## 4. 动画的基础原则在像素语境中的使用

- **Timing & Spacing**：什么时候发生、相邻姿态差多少。位置增量越大，一般视觉速度越快。
- **Anticipation**：角色挥剑前先蓄力，提灯被风吹前可先有微弱偏转。
- **Squash & Stretch**：柔软物体弹跳可形变；硬玻璃瓶不该随便拉伸。
- **Arcs**：手、头、布料末端常沿弧线运动，而不是机械折返。
- **Follow Through / Overlap**：主运动结束后衣角与发丝稍晚停下。
- **Staging**：主要动作清楚，次级特效不能盖过主体。
- **Exaggeration**：小画布允许适度夸张关键姿态，避免过度“真实物理”导致不可读。

这些属于广泛使用的动画原理；具体在像素画中的应用可参考 [Saint11 的 easing、squash-stretch、subpixel、looping 等专题](https://saint11.org/blog/pixel-art-tutorials/)。

## 5. 循环循环：不是只让 F0=最后一帧

若帧数组为 [A,B,C,D] 且播放为 A→B→C→D→A，**不需要通常再重复 A 作为额外最后一帧**，否则会在 A 位置多停一下。关键是 D→A 的速度和形体变化像正常的一次过渡。

检查流程：
1. 从 F0 开始正常播放 10 个循环。
2. 单独播放倒数两帧 + F0 + F1 的首尾邻接。
3. 观察轮廓/气泡是否瞬移、光源是否不合理闪灭。
4. 用不同播放速度检查跳帧；停止/慢放检查“哪一帧变差”。
5. 需要时让物体回归中性姿态，或设计周期位置函数并按整数像素采样。

**工程诊断**：像素帧差百分比、稳定锚点位移、各层变化面积等可以做告警，但不等于美感分数。火焰和爆炸可能故意产生较大帧差；静止层产生微小像素差却高度可疑。

## 6. 物品循环案例：血瓶

**目标**：瓶外形完全稳定，内部液面在 0、+1、0、-1 像素之间变化；气泡从瓶内缓缓上升，少数高光偶尔改变。注意液体总体“质量感”，不要改变瓶外轮廓与装液高度到无法解释的程度。

分层：bottle_outline（静止）→ glass_base（静止）→ liquid（4–8 帧）→ bubbles（4–8 帧）→ glass_highlight（大部分静止）→ spark（低频变化）。

关键工作步骤：
- 在液面变化前，完成四个稳定的瓶身主帧（可共用静止 cel）。
- 明确液体边界遮罩 mask，只允许液体像素在内部区域移动。
- 用 1× 看液面是否自然；放大检查气泡每帧路径是否连续。
- 若液体看起来像闪烁的红色噪点：删掉散点，改成完整色块，缩小波幅，减少随机性。
- 用“背景无特效版本”检查基础动画；再渐进加回气泡/火花。

## 7. Aseprite 工具操作对应

- 新增与复制帧：[Animation](https://www.aseprite.org/docs/animation)。
- 前后帧半透明参考：[Onion Skinning](https://www.aseprite.org/docs/onion-skinning/)。
- 每帧独立持时：[Frame Duration](https://www.aseprite.org/docs/frame-duration/)。
- 动作命名与方向：[Tags](https://www.aseprite.org/docs/tags)。

PixelWeave 当前部分支持这些功能；尤其“单帧持时、onion skin、clip mask”等要作为产品开发需求，而不是声称已经全部实现。

## 8. 结业任务

提交两件循环动画：
- 24×24 药瓶：至少 4 帧，外轮廓固定，液体和气泡逐帧变化。
- 24×24 提灯：至少 6 帧，火焰有主火舌与次级亮部变化，灯框稳定。

**验收**：用户不用放大便能感知“液体在动/火焰在燃烧”；单独禁用动态层后仍是合格的静态道具；10 次循环后没有明显接缝或耀眼噪点。不要以“帧差很大”作为成功条件。

# L2 实验：从静帧到分层逐帧循环

来源：[Slynyrd Intro to Animation](https://www.slynyrd.com/blog/2018/8/19/pixelblog-8-intro-to-animation)、[Items](https://www.slynyrd.com/blog/2019/12/21/pixelblog-24-items)、[Aseprite Linked Cels](https://www.aseprite.org/docs/linked-cels/)。

## 案例 A：玻璃药水，8 帧，6 层

[打开原创 Scarlet Vial 工程](../examples/reference/scarlet-vial.layered.json)。

稳定层：shadow、glass、reflections、stopper；动态层：liquid、bubbles。稳定层应当在 8 帧中逐像素完全一致。

| 帧 | 液面偏移（逻辑像素） | 气泡 (x,y) | 事件 |
| --- | ---: | --- | --- |
| F0 | 0 | (12,18) | 已在液体内 |
| F1 | 0 | (12,17) | 上浮 |
| F2 | -1 | (12,16) | 上浮 |
| F3 | -1 | (12,15) | 上浮 |
| F4 | 0 | 无 | 到液面附近消散 |
| F5 | 0 | 无 | 休止 |
| F6 | +1 | 无 | 休止 |
| F7 | +1 | (12,19) | 底部新泡生成 |

F7 → F0 的气泡仅移动 1px，新的气泡出现由 F6→F7 表示；旧泡消失被解释为接近液面后破裂。气泡不应突然跑到瓶外。**这是一套教学动作设计，并非流体物理仿真。**

逐帧修改路线：先单独播放 liquid；再播放 bubbles；然后与静止玻璃合成；最后检查 F7→F0。故意在 F2 把气泡挪到 (12,10) 形成错误工程，用液体遮罩检查发现后修回 (12,16)。

## 案例 B：火焰与金属不可混为一个动态层

[提灯](../examples/reference/hearth-lantern.layered.json) · [独立火焰](../examples/reference/ember-flame.layered.json)。

固定炉芯/外框与动态火焰分开。先遮掉内核只看外焰的姿态，再加回内核、最后才加 sparks。不要让灯架每帧改变形状。主要节奏来自峰值、过渡、停留与回归，而不是无节制加帧。

## 案例 C：旗杆与布面

[Wind Banner 8 帧](../examples/reference/wind-banner.layered.json)：staff 完全不动，fabric 末端变化，folds 跟随面料弯曲。对比“固定杆正确版”和“杆子也每帧乱跳的错误版”，检查稳定锚点。

## 模型必须输出怎样的修复

修复请求必须指定图层 ID、准许修改帧、像素矩形区域、冻结图层。系统验收：数据无非法符号、冻结层逐像素一致、修改像素没有越过可修改区域。程序帧差只能报警，不能证明视觉美感；同一动作仍需在 1× 速度下人工观看 10 次。

**出口门槛**：静态结构稳定、动作语义明确、事件有诞生/持续/消散、首尾不突然闪烁、可以导出后回读完整 JSON。

# L3 · 角色动作、布料、自然效果和小型特效

**定位**：能做出不僵硬的角色 Idle / Walk / Run，并让火焰、布料、烟雾等次级物体遵守基本运动逻辑。

## 1. 角色动画的准备

先确定角色视觉规格：视角（正侧背/3⁄4/俯视）、身高（逻辑像素）、头身比、脚底基线、主色板、固定饰物和服装锚点。不要每帧单独重画造型，否则服装和脸的“身份”很容易漂移。

原尺寸静态 Idle 主帧通过后，先做简化人体 Dummy：头/胸/胯/臂/腿几个单色块。**先让 Dummy 的运动正确，再着色加配饰**。

来源：[Slynyrd Motion Cycles](https://www.slynyrd.com/blog/2020/1/23/pixelblog-25-motion-cycles)、[Saint11 教程合集](https://saint11.org/blog/pixel-art-tutorials/)。

## 2. Idle 动画的三个层次

1. 重心/胸腔：呼吸带来极微小的轮廓变化或身体上下位移。
2. 次级运动：头发、衣角、绳带/饰品有延迟响应，频率不必一致。
3. 表演：眼神、视线、眨眼，节奏疏密可不规则，但需可控循环。

低分辨率角色未必适合每帧都全身上下浮动。许多令人舒适的 Idle 只有 2–4 帧细微变化。观众应感到“在呼吸”，不是“角色一直在抽搐”。

## 3. Walk 与 Run

标准步行动画可按以下关键姿态规划：接触 Contact → 下沉 Down → 越过 Passing → 上升 Up → 反脚接触。左右循环在对称角色上可以镜像，但武器、衣服、头发不对称的角色需手工校正。

重要问题：
- 脚接地时不能大范围滑动（foot sliding）。
- 躯干、头、肩、胯之间要保持有意义的体积与受力关系。
- 手臂自然摆动方向往往与同侧腿不同步。
- 动作进入/离开场景的基线和碰撞盒要稳定。
- Run 的空中相、接地时间和躯干前倾通常比 Walk 更明显。

参考：[Slynyrd Motion Cycles](https://www.slynyrd.com/blog/2020/1/23/pixelblog-25-motion-cycles) 与 [Pixelblog 8](https://www.slynyrd.com/blog/2018/8/19/pixelblog-8-intro-to-animation)。

## 4. 材质和次级动画分开

- 头发、飘带：根部与头部/身体绑定，末端延后响应。
- 布料/旗帜：褶皱方向受风向、重力和固定点影响；不要让整个形状每帧随机改变。
- 火焰：固定基部、上方变化较大，内核明亮、边缘暗，变化有方向偏好。
- 烟雾：体积逐渐上升、松散和淡出，而非突然出现大量碎点。
- 水花：依碰撞/冲击方向展开、破碎、落下；短暂快速而非长期匀速漂浮。
- 魔法光：有主发光面与辅助小粒子；亮点运动应服从主光节奏。

参考：[Saint11 火焰/烟雾/布料/特效专题](https://saint11.org/blog/pixel-art-tutorials/)。

## 5. 动画分层的规范化命名

建议 root/body/face/hair/cloth/equipment/fx/shadow，或者语义相近的名称；每层提供稳定锚点 parentAnchor，未来支持关联层变换。禁止用 color_1、red_layer 之类无含义的名称作为常规做法。

## 6. 练习顺序

A. 16×16 火焰 6 帧：脚底固定、顶部不同形状。  
B. 32×32 布旗 8 帧：旗杆固定，褶皱顺风移动。  
C. 24×32 Dummy Idle 4 帧：脚下基线固定。  
D. 24×32 Dummy Walk 6–8 帧：接触、下沉、经过、上升。  
E. 在 D 上添加服装、头发与次级运动。

**通过条件**：动态的主动作有表现力；静态结构不漂移；低分辨率不会因为服饰细节而牺牲动作清晰性。无法通过时返工 Dummy 的关键姿态，而非继续叠加发丝、粒子。

# L4 · 场景构图、景深、瓦片、透视与氛围

**前置**：掌握静态材质和至少一种小规模循环动画。**目标**：把多个单独正确的像素素材组织成整体有层次的世界，而不是“物体越多越好”。

## 1. 场景设计从视觉叙事开始

开画之前回答四个问题：观众首先看什么？故事发生在哪里？哪些位置需要保留安静的负空间？哪一种变化代表时间在流逝？

建议把视觉层分为主焦点、次焦点、支撑环境、背景空域。不要让所有东西发亮或同步运动。先用单色大形体（thumbnail）做至少两个方案，选定构图，再开始逐像素细化。

## 2. 投影法与像素尺度要在同一场景统一

常见视角：侧视、俯视（Top-Down）、3/4 斜俯视、等距（Isometric）及舞台式正面投影。人物、家具、地面、建筑必须遵循同一空间规则；不要将正侧面道具直接放入斜俯视场景而不做调整。

等距项目常借助固定像素斜率（例如 2:1 的画线节奏），但这只是特定等距投影风格，不能当成对所有视觉项目的固定规定。参考：[Slynyrd Graphical Projection Part 2](https://www.slynyrd.com/blog/2018/4/12/pixelblog-4-graphical-projection-part-2)。

## 3. 场景景深的五个信息通道

1. 遮挡前后关系（谁挡住谁）。
2. 色彩与明度：远景常因空气透视变得更接近背景色，具体随气氛调整。
3. 细节密度：近景可精细，远景应省略大量噪点。
4. 边缘对比：焦点和前景可更锐利，背景不必同等刺眼。
5. 动态视差：前景在相机运动时相对更快，远景慢。

景深首先靠静态图层成立，再加 Parallax；做不好静态景深，视差难以补救。参考：[Slynyrd Parallax Scrolling](https://www.slynyrd.com/blog/2019/11/12/pixelblog-23-parallax-scrolling)。

## 4. Tilemap 与大场景拼接

Tile 是可复用的小图块，Tileset 是图块集合，Tilemap 是由图块索引组成的场景。分清“复用纹理”和“唯一的地标建筑”。地面材质、砖缝、墙体适合复用；主焦点通常需要更独特的轮廓。

检查每个 Tile 的四边接缝，确保邻接时没有断缝或不应出现的重复地标。参考：[Aseprite Tilemap 官方文档](https://www.aseprite.org/docs/tilemap/)。

## 5. 雨夜车站分层任务

建议低分辨率场景试验画布：96×54 / 128×72，或根据最终目标自定义。

由远到近：
- sky：大天空色块、云与少数星点/环境噪声。
- skyline：电线杆、远处建筑和层叠屋顶的剪影。
- station：候车亭、站牌、售票机、平台、栏杆。
- lights：站牌灯箱、售票机暖光，及其地面反射。
- rainfall_back：背景稀疏细雨；密度低，速度慢。
- subjects：角色或列车；用固定基线表示与站台关系。
- rainfall_front：前景大雨丝或偶发落滴；密度适度。
- foreground：地面近景、栏杆或伞檐，建立沉浸感。

**运动主次**：车站主体保持安静，天空云层极慢，灯光低频微动，雨滴快速重复；若加入列车，列车运动成为某段时间内最高对比度的动态焦点。

## 6. 夜景配色要避免“全是蓝紫色”

夜色的正确视觉表达不等于把所有颜色乘一个蓝色滤镜。需要明确可见光：冷环境光、暖人工光、屏幕光、反射、人物局部受光。保留重点建筑在灰度关系里的可辨识性；暗处可以简化，但不能大面积随机抖点。

## 7. 高级风格：恐怖与 Ditherpunk

恐怖来自未知信息、视线阻隔、留白、有限光源、不对称空间、缓慢的运动违和感。Ditherpunk 则可以用有秩序的抖动图案、强烈对比和粗粝限制色板表现复古恶梦感。两者可以结合，但**先有场景叙事，再决定多少抖动**。不要把骷髅、血、蜡烛、裂缝等元素无限堆砌。

## 8. 结业门槛

交付：至少三层可独立显示的静态车站景深图，包含明确前中后景、一个主光源、一件可读的关键道具。随后增加少量雨和灯光循环。隐藏动态层后，场景本身仍应具有合理构图。

# L5 · 动态像素艺术壁纸：从场景到耐看的循环作品

## 1. 动态壁纸和游戏动效的目的不同

游戏动效往往要立即传达状态与反馈；壁纸的主要任务是**长时间观看不疲劳、持续提供空间氛围和轻微叙事**。它应容许观众把注意力移回桌面工作。避免无休止的高频闪烁、全屏粒子、突然的镜头摇晃和抢占视觉焦点的循环噪声。

## 2. 先建立作品的美学章程（Art Bible）

一个完整壁纸项目开工前，应有一页固定规则：

- 一句话主题，如“末班车离开后的无人车站”。
- 观众的视点：镜头高度、视角、画框宽高、主焦点与负空间。
- 世界观/艺术风格：暖心日常、JRPG 暮色、诡异 Ditherpunk 等。
- 基础分辨率与像素密度：不要未经设计直接拿高清画布逐像素绘制。
- 色彩：主色 2–3 组、光源配置、背景/焦点对比关系。
- 图层：前/中/远景、局部发光、天气、人物、可动独立资产。
- 运动：每层运动类型、周期、强度、方向、是否同步。
- 发布用途：Windows 桌面动态壁纸、手机竖屏、Web 展示或 WebM 作品。

## 3. 三个时间尺度

**微循环**（约 0.5–3 秒）：火焰、气泡、滴水、呼吸；短而精确。  
**中循环**（约 3–12 秒）：树叶摆动、云影、路灯亮度、细雨密度。  
**长循环**（约 12–60 秒及以上）：列车经过、角色小动作、昼夜情绪片段。

以上为可行的课程设计参考范围，不是统一行业标准。完整主循环需要协调短周期；若循环严格同步，设计总时长让各模块周期整除总时长，或者将模块设计为可随意采样且不产生明显突变的数学周期。

## 4. 视差与画布

先设计相机是否移动。固定镜头的氛围壁纸**不必强制加视差**。若镜头微移动，前景相对快、远景相对慢；尽量按逻辑像素的整数增量运动。视差背景在滚动方向应可平铺，避免出现接缝。

构建时使用逻辑画布，导出时按明确的最近邻缩放规则。非整数缩放有时可通过优化采样处理，但默认禁止无意的线性插值模糊。参考：[Slynyrd Parallax Scrolling](https://www.slynyrd.com/blog/2019/11/12/pixelblog-23-parallax-scrolling)；[Godot Nearest Texture Filter](https://docs.godotengine.org/en/4.5/classes/class_canvasitem.html)。

## 5. 风与雨的运动规则

雨分前后景：远景稀薄低对比，近景可少量高亮大滴。不是将整个屏幕撒上等量斜线。每粒雨可采用“初始坐标 + 时间×速度 + 取模”的确定性运动，保证可复现，不采用逐帧重新抽随机数。

光照统一：雨丝受灯光影响时才靠近亮色；地面反射的方向与灯箱/路灯位置匹配。雾应弱化远景对比，而不是让所有东西都覆上等亮灰色。

## 6. 无限循环与防视觉疲劳

检查：
1. 至少连续观看 60 秒，判断哪里最抢眼。
2. 反复播放循环接缝，观察明暗、镜头与对象状态是否跳变。
3. 在 1× 分辨率与实际桌面尺寸下分别检查。
4. 检查桌面图标可能覆盖的位置是否有足够负空间。
5. 检查暂停/恢复、低帧率、最小化时的表现；不要让性能开销持续增长。
6. 可关掉光效与粒子后，主体构图是否仍成立。
7. 避免频繁高对比闪烁，对光敏用户保留降低动态强度的选项。

## 7. 作品的交付规格（PixelWeave 自定）

最小项目建议包含：
- scene.json：构图、相机、背景色、层级和资产引用。
- assets/：每个资产的独立分层 JSON。
- timeline.json：动作、时长、循环方式和关键事件。
- palette.json：共享环境色板及局部例外。
- preview.png：静态缩略图、便于 Gallery 展示。
- wallpaper.html：脱离模型服务后可离线运行的浏览器壁纸。
- output.webm / sprite-sheet：按需要导出。
- credits.md：原创性、第三方教程与素材授权记录。

**注意**：这是目标工程规范，不是声称现有 v0.3 已实现上述所有文件。

## 8. 终极综合训练

主题：雨夜无人车站，一瓶有微光的红药水放在售票窗口，远处偶尔驶过慢车。

先做一张静态全景；确认视觉主次。然后分别加入 4 个可独立控制的动态：药液、灯箱、雨滴、远处列车。最后做夜色、灯光与玻璃反射的一致性检查。

**合格作品不是“元素多”，而是“主题清楚、画面耐看、时间流动可信”。**

来源：[Slynyrd 风景与视差](https://www.slynyrd.com/pixelblog-catalogue)、[Saint11 风格一致性](https://saint11.org/blog/consistency/)、[Aseprite Spritesheets](https://www.aseprite.org/docs/sprite-sheet/)。

# PixelWeave · LLM 像素动画创作编译规范

> 本章是 **可执行的创作操作手册**，不是用“画得更精美”这种空指令指导模型。  
> 受众：提示词架构师、Agent 开发者、人工美术总监。  
> 目标：把主题 → 构图 → 剪影 → 材质 → 分层 → 动作 → 审核 变成可追踪操作。

## 1. 为什么“一次输出整幅像素画”不可靠

例如 32×32×8 帧×5 层，每层每帧都有需要校验的独立像素与颜色映射。一次完整文本输出不仅长，而且容易出现错误行宽、图层偷懒重复、主体造型漂移或内部运动无物理关系。

因此 **逐层生成、逐层冻结、局部补丁修复** 比整体重做更合理。成功不由文本“看起来复杂”定义，而由渲染后的像素图、循环预览及人工检查决定。

## 2. 分层创作状态机

状态从 P0 进入 P8，不允许模型越级跳过验证：

| 阶段 | 输入 | 输出 | 通过条件 |
| --- | --- | --- | --- |
| P0 Brief | 主题、用途、尺寸、投影、风格与观看背景 | 结构化美术任务书 | 无矛盾，目标明确 |
| P1 Director | Brief + 构图技巧 | 1–3 种形体方案、主焦点、色板、光源 | 方案满足景别和材质逻辑 |
| P2 Silhouette | 已选方案 + 01 章 | 仅轮廓层主帧 | 1× 可读，像素簇清晰 |
| P3 Palette/Form | 冻结剪影 + 02 章 | 色板、主体受光体积 | 灰度关系正确，材质分工明确 |
| P4 Layer Split | 03 章 + 运动意图 | 图层角色与遮挡次序 | 稳定层与动态层分开 |
| P5 Motion | 04/05 章 + 已冻结图层 | 各层关键姿态、帧变形 | 运动明确，身份与稳定锚点不变 |
| P6 Cleanup | 帧序列 + 错误定位 | 只修指定层的 bbox 或帧 | 无结构回归、数据仍可解析 |
| P7 Review | 渲染 PNG、逐帧差异、完整循环 | 问题清单、分数与人工复审意见 | 硬性错误为 0；关键美术问题可接受 |
| P8 Publish | 全部源资产与元数据 | 分层 JSON、精灵图、预览、来源记录 | 可以导入、可编辑、可重现 |

**禁止 P5 改变未经批准的核心轮廓。** 如确需大改，回到 P2 重新审批并创建新版本；不要悄悄覆盖旧素材。

## 3. 必须由系统硬性校验的约束

当前 PixelWeave layered-v1 规范：
- format = pixelweave/layered-v1。
- width/height 必须为 8–64 的整数。
- fps 必须为 1–24 的整数。
- layers 为 1–12 层，ID 唯一、可引用，图层的 name/visible/opacity/x/y 有定义。
- 所有图层 frames 数量一致，1–16 帧；每帧有 height 行，每行精确 width 个字符。
- palette 中 "." 指向 transparent；键为单字符 ASCII，值为 #RRGGBB 或 transparent，最多 32 项。
- 每个像素符号必须在色板中声明；所有 JSON 数据都应视为不可信输入，禁止执行来自模型的任意代码。

以上为 **版本化软件接口**；不是像素艺术的通用分辨率规范。改格式时必须升级版本并提供迁移，不可偷偷改变模型预期。

## 4. 生成任务应包含的上下文

最小上下文包（一次任务只加载相关内容）：

    role: Sprite Animator
    stage: P5 Motion
    goal: 生命药剂的红色液面轻微晃动
    renderResolution: 24x24
    assetId: potion_crimson
    activeLayer: liquid
    frozenLayers: outline, glass, cork, highlights
    allowedFrames: 0..5
    stableAnchors: bottleMouth, bottleBase, leftEdge, rightEdge
    palette: approved 8-color mapping
    technique: 04-ANIMATION, section 6
    failureToAvoid: contour jitter, inconsistent liquid volume, random spark noise
    output: strict layered JSON or scoped patch
    validation: schema, mask boundaries, preview, temporal check

AI 必须知道“可改与不可改”的边界。仅指定主题而不指定稳定层，很容易得到每一帧瓶子形状不同的伪动画。

## 5. Prompt 分成不同角色，而不是一锅端

**Art Director**：确定风格与目标、主焦点、投影、色板、光向、材质重点；输出小型 JSON 的 plan，不输出像素。

**Silhouette Artist**：专注轮廓与负空间；优先一帧和 1–2 色；输出轮廓图层，不管动画。

**Palette/Material Artist**：在已批准轮廓内加入光影、材质，禁止随意修改体积轮廓。

**Motion Artist**：利用已有静态帧生成少量关键帧，保持 stableAnchors；先变形体、液面、火焰等运动本体，后做辅助粒子。

**Reviewer / Repairer**：只回答“有什么问题、具体在哪里、需要修哪一层”，再输出局部补丁；不要同时替换整个世界观、色板、画法。

每个 Agent 可由同一个普通 LLM 执行，**不要求五个不同模型**。

## 6. 技巧检索示例（Skill / RAG）

任务：“24×24 药水液面做 6 帧缓慢循环”。

应该加载：
1. Core 中“轮廓固定、按语义分层、有限色板、结构校验”。
2. Technique 中 [03 血瓶结构](03-ASSET-DESIGN.md)、[04 血瓶动画](04-ANIMATION.md)、[02 液体](02-COLOR-LIGHT-MATERIAL.md)。
3. Case 中已完成的药瓶结构和实际编辑层。
不应加载角色 walk cycle、isometric 房屋构图、256 色场景或高级相机漫游。

任务：“横向 16:9 雨夜车站长循环”。

应该加载 Core + [06 场景](06-SCENE-DESIGN.md) + [07 壁纸](07-WALLPAPER.md) + 雨滴层 / 灯光层的对应案例。**应先做场景静帧再做动画，不要试图让模型在一个 96×54 文本矩阵中同时创造所有图层与所有雨滴。**

## 7. 输出修复策略

**Data errors**：JSON 格式破损、行宽错误、缺少符号、图层数量不一致。程序应明确指出错误层、帧、行及允许值，自动重试生成目标层；不需要“艺术家式评论”。

**Geometry errors**：剪影变形、液体出界、角色脚滑。直接生成对应局部的修改计划和 bbox。

**Artistic errors**：不够有质感、构图空、色彩脏、主次不清。必须关联到具体可观察问题：“第 4 帧的红色高光变成 15 个 1px 单点”“轮廓左下缘有双像素突起”，不能只发形容词。

**Resource budget errors**：限制上下文、输出 tokens、重试次数、并行层数。可降低练习规格为 16×16/4 帧，或只让模型生成变化部分，不能直接跳过校验。

## 8. 稳定层冻结契约（未来应落地至代码）

冻结层（frozenLayers）的像素哈希不许改变。只能修改 activeLayer 和 allowedFrames 内的指定 bbox。系统对每次补丁执行：
- 基于上一版本制作备份和不可变快照。
- 校验大小/色板/范围合法。
- 应用局部变动。
- 比较所有冻结层与 stableAnchors 的差异。
- 重算动画指标与视觉预览。
- 提供 Accept / Reject / Revert。

PixelWeave v0.3 目前实现了图层级的人工编辑、JSON 验证和生成重试；**像素哈希冻结、局部补丁协议和真正的视觉评审循环尚属待实现任务**。

## 9. 建议的模型评测协议

选 5 个测试主题：单色钥匙、血瓶、火焰、角色 Idle、雨夜车站。每个主题采用相同条件、相同知识加载方案和 3 次生成预算，在至少 3 个不同模型上记录：
- JSON 首次通过率和重试次数。
- 单图层的静态轮廓可读率（人工盲评）。
- 帧之间稳定锚点平均位移。
- 1× 展示与放大图的材质辨识。
- 循环观看评分（人工）。
- 生成 token、费用、时间。
- 局部重绘后未修改层的差异量。

**不能用几张好看样张代替完整模型基准测试。**

# PixelWeave · 像素画与动画质量验收规范

## 1. 评测必须分三种证据

**Hard Gate（硬性错误）**：格式解析失败、非整数网格、图层帧数不一致、未定义色板字符、图层越界、工程无法导回。硬错误必须为零，才允许进入审美评分。

**Diagnostic（自动风险诊断）**：帧差、孤立像素数、无意义近似色、稳定区域变化量、循环帧差等。系统只报风险和位置，不自称“这张画不美”。

**Aesthetic Review（美术审阅）**：造型、色彩、材质、动作表演、故事性、风格统一、节奏舒适。这些主要依靠有经验的人类判断；使用视觉模型评估也必须记录可能的误判与数据来源。

## 2. 素材评分卡：100 分（PixelWeave 自拟）

| 维度 | 权重 | 观察要点 |
| --- | ---: | --- |
| 剪影与辨识度 | 20 | 1× 原尺寸识别、形体组织、负空间 |
| 像素簇与边缘质量 | 15 | 连续簇、台阶节奏、非刻意噪点 |
| 色彩与明暗 | 15 | 光源统一、层次分组、色板效率 |
| 材质与视觉质感 | 15 | 玻璃/金属/液体等可辨，反光逻辑 |
| 动画连贯性 | 15 | 结构稳定、动作清楚、节奏合理 |
| 循环品质 | 10 | 首尾衔接、无显眼突变、不重复顿挫 |
| 叙事与风格一致性 | 10 | 主题、投影、整体气质与背景统一 |

**评分解释**：90–100 适合精品画廊候选；80–89 可用且需细抛；70–79 基础达标但欠完整；70 以下返回缺点最多的环节。此阈值是本项目的可修改工作约定，尚未通过专家打分样本校准，不应伪称业内标准。

## 3. 动画检测：规则 ≠ 审美

### 3.1 解析与图层完整性

- width、height、frameCount、palette、layerCount、opacity、位移全部合规。
- 隐藏特效层后主体仍完整。
- 没有本应始终固定的瓶身结构在帧间变化。
- 每一帧在同一逻辑分辨率下渲染。

### 3.2 帧间差异率

定义：

    changeRatio(t) = count(pixelColor(frame_t) != pixelColor(frame_(t+1))) / (width*height)

该指标在 **整幅合成帧** 计算能给出总体动量；在 **独立图层** 计算能找出变化来源。它不能回答物体动画是否自然；例如极小的闪烁眼睛只有很少像素变化，但可以十分突兀。

### 3.3 稳定锚点位移

为瓶塞、瓶底、脚底、眼睛或角色服饰设置稳定锚点，衡量各帧是否相对主层漂移。对浮动资产可以允许统一 root motion；检查时先减去 root motion，不能把整体有意移动算作轮廓坏掉。

### 3.4 循环断点

比较末帧→首帧与任意相邻帧的相对变化规模，提醒“接缝落差异常”；但静态/小循环不强制首末相同，火焰、风、爆炸等需结合动作意图分析。

### 3.5 视觉噪点

统计孤立像素、短命像素（只存在一帧）、近似重复颜色、碎裂像素簇；对星空、火花、雪雨类粒子图层设置例外规则。**没有一个能通用于全部艺术风格的“孤点上限”。**

### 3.6 性能与技术

- 透明边缘没有意外黑边、缩放无无意模糊。
- 时间线能暂停、逐帧寻址、导出同样画面。
- 目标低端设备上内存不随循环持续增长。
- 发光/闪烁不过度刺激，支持 reduced-motion/减少特效。
- 资产 JSON 重新导入后每层每帧像素完全一致。

## 4. 人类审查顺序

1. 原尺寸不带说明观察 3 秒：它是什么？主题明确吗？
2. 转黑白、隐藏特效：还有体积和焦点吗？
3. 放大 8× 查看轮廓：台阶是否有意图？
4. 分离每层：是否画了本不属于该层的东西？
5. 以正常速度循环 10 次：是否有刺眼的闪点和抖动？
6. 最后单看末帧接回首帧：是否停顿或位移突变？
7. 改在纯黑/纯白/作品目标背景展示：对比是否崩掉？
8. 保存问题截图、帧号、图层 ID，发回“具体可修的描述”。

## 5. Failure Taxonomy：优先改根因

| 失败 | 可能根因 | 首选处理 |
| --- | --- | --- |
| 画面像马赛克没形 | 剪影不稳、缺乏像素簇 | 回 L0，只返工形体 |
| 很细但不精致 | 无意义细纹、颜色过多 | 减少纹理与高光，整理明暗 |
| 所有物体看起来塑料 | 材质反光模型一样 | 分别重建玻璃/金属/木头的亮面结构 |
| 药水像亮红噪点 | 气泡过多、液面逐帧随机 | 冻结玻璃，修液体层和粒子频率 |
| 动画抖、角色服饰变形 | 每帧无约束重绘 | 固定造型层、使用 stableAnchors |
| 动画“很动”却没表现力 | 没关键姿态与节奏 | 回关键帧，删掉辅助特效 |
| 场景华丽但主题模糊 | 焦点过多、对比平均 | 回缩略图，重分主次 |
| 壁纸看一会儿很累 | 高对比闪烁、同步粒子 | 设运动主次，降频、降亮度 |

## 6. 审核记录格式

每次审查保存：
- assetId、revision、brief、sourceLessonIds、modelId（若由 LLM 生成）。
- hardGate: pass/fail；hardGateErrors: []。
- diagnostics：frameDiff、anchorDrift、loopDiscontinuity、paletteCount、isolatedPixelWarnings。
- reviewScores：上述 7 项各自打分，并标 reviewerType = human / heuristic / visionModel。
- issues：level（blocker/major/minor）、layerId、frameIndices、bbox、问题、建议的最小修复动作。
- finalDecision: accept / revise / reject；附前后版本对比路径。

## 7. L0–L5 的门槛差异

L0 只审剪影与像素簇；L1 加入光影材质；L2 要求动画和循环；L3 增加身体受力、走路接触点；L4 增加构图/透视/空间；L5 增加长时间观看感受、性能与壁纸发布完整度。低级练习不要被高级要求压垮。

参考：[Pixel Joint 常见错误](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)、[Slynyrd Intro Animation](https://www.slynyrd.com/blog/2018/8/19/pixelblog-8-intro-to-animation)、[Aseprite 时间线与 Cel](https://aseprite.org/docs/basics/)。


## 本轮实证边界（v1.1）

新增机器检测：分层资产结构、稳定层哈希等价性、气泡与液体逐帧像素叠合、单层补丁的授权区域/帧校验。它们可以客观地检查具体几类技术错误，却**不能**评判美商、构图、角色表演和视觉风格。

资产库中的六个范例由项目原创代码生成，状态为“可复现并通过结构检查”；没有外部专家盲审，更不能拿来作为模型完成度的满分样板。未来对照实验必须记录：相同题目、相同文本模型、是否注入知识、生成失败重试次数、结构性告警、人工匿名评分和生成费用。未做真实盲评前，不给 v1.1 自称 90 分。

# 10 · 十个循序渐进的原创实战项目

**用途**：人类训练课程 + PixelWeave 文本模型的回归评测集合。每个项目必须提交可编辑源文件、原尺寸 PNG 和简短复盘。难度按照依赖关系递进，不要求固定花费小时数。

## 项目 01 — 一把会被认出的钥匙（L0）

- 画布：16×16；颜色：黑/透明，之后可加两色。
- 要求：只画一个正视钥匙。先出 3 个不同剪影，再选最好的一版。
- 检查：钥匙柄孔洞清楚；齿部有辨识度；没有无意的轮廓凸刺。
- 禁止：先做金属高光/魔法特效来掩饰不清晰剪影。
- 参考：[L0 轮廓](01-FOUNDATIONS.md)。

## 项目 02 — 一瓶静止的血药水（L0/L1）

- 画布：24×24；最多建议 8 色。
- 图层：轮廓/瓶塞/玻璃基底/红药液/玻璃高光。
- 检查：主体静帧结构完全闭合；液体被限制在瓶体内部；受光方向统一。
- 复盘：玻璃与液体材质为什么不同？哪些像素是不可删的？
- 参考：[色彩材质](02-COLOR-LIGHT-MATERIAL.md)、[道具](03-ASSET-DESIGN.md)。

## 项目 03 — 金属提灯 vs 玻璃魔晶（L1）

- 画布：两件 24×24 静物；共享主环境色但可有自己的强调色。
- 目标：金属反射与水晶切面必须有明确区别。
- 对照：原尺寸能看懂吗？投影和亮部方向一致吗？
- 检查：亮点不均匀撒满；暗部不是机械的外围等宽色带。

## 项目 04 — 流动的生命药剂（L2，PixelWeave 首个关键里程碑）

- 画布：24×24 或 32×32；建议 4–8 帧。
- 固定层：outline、cork、glass_base、glass_highlight。
- 动态层：liquid、bubbles、偶发 spark。
- 动作：液面以小振幅起伏，气泡沿明确路径上升，液体始终在容器内。
- 验收：所有固定层帧间像素完全一致；移除特效后可看清液面；十次循环无突兀跳变。
- LLM 检查：只让模型修改 liquid/bubbles，禁止改 frozenLayers。
- 建议参考：[Slynyrd Items](https://www.slynyrd.com/blog/2019/12/21/pixelblog-24-items)。

## 项目 05 — 提灯火焰的性格（L2）

- 画布：24×24；建议 6–8 帧。
- 动态层：fire_core、fire_outer、sparks、lit_surface。
- 火焰的固定点与灯芯位置一致，上端变化更剧烈，环境光与火势相呼应。
- 检查：明暗与火焰体积相关，不能变成彩色随机电视雪花；灯笼金属框架稳定。

## 项目 06 — 风中的布旗（L3）

- 画布：32×32；建议 6–8 帧。
- 固定点：旗杆与连接处；动态：布面、褶皱、末端边缘。
- 评价：幅度有快慢，风向明确，旗面不是随机改变形状。
- 参考：[Saint11 Fabric](https://saint11.org/blog/pixel-art-tutorials/)。

## 项目 07 — 会呼吸的角色（L3）

- 画布：24×32 或 32×48；Idle 4 帧。
- 完整化：角色单色 Dummy → 关键姿态 → 上色 → 发丝/衣摆滞后。
- 评价：头、身体、脚底基线和人物身份保持一致；不出现帽子/发型随帧改变的情况。
- 参考：[Slynyrd 动画入门](https://www.slynyrd.com/blog/2018/8/19/pixelblog-8-intro-to-animation)。

## 项目 08 — 四个接触姿态的步行（L3）

- 画布：同项目 07；可先用 4 个关键姿态再补 6–8 帧。
- 重点：Contact/Down/Passing/Up，手脚配合、脚滑、重心。
- 先设计 Dummy，验收后才能加头发、外套和武器。
- 参考：[Slynyrd Motion Cycles](https://www.slynyrd.com/blog/2020/1/23/pixelblog-25-motion-cycles)。

## 项目 09 — 安静的雨夜站台（L4）

- 画布：96×54 或 128×72 逻辑像素。
- 先交静态 3–5 层：skyline、platform、station、lighting、foreground。
- 再加：两组不同速度雨滴、灯光轻微变化、远处缓慢云层。
- 检查：前中后景不混淆；单个光源真实影响邻近物体；背景没有过度重复的点。
- 参考：[场景](06-SCENE-DESIGN.md)。

## 项目 10 — 动态像素壁纸精品（L5）

- 画面：16:9 横向；有独立的 Art Bible 和明确的视觉主角。
- 必要元素：完成度高的静态场景、3–5 组各具功能的动态层、全时长循环、低干扰光效。
- 提交：源资产/图层、时间线、渲染 HTML 或视频、静态缩略图、可追溯版本与评价报告。
- 验收：让人连续观看至少 60 秒，仍然觉得主次有序且不疲劳；首尾无明显断点；桌面图标区域有合理负空间。
- 参考：[壁纸工作流](07-WALLPAPER.md)。

## 每个作品必须存档的最小信息

    workId / title / learningLevel
    brief / dimensions / palette
    sourceLessons / referencedSources
    layerPlan / stableAnchors / animationNotes
    exportedFiles / projectJSON
    hardGateResult / aestheticScores / issues
    revisionHistory / reviewerNotes

严禁将由程序手绘的演示样品写成“LLM 自动生成成果”。真正的模型生成测试必须保存 modelId 和生成记录。建议每一关至少尝试两个版本，比较“第一次尝试 vs 按质检返修”的改善。

## 学习终点与项目真正的工程目标

完成 01–04：可以用 LLM 搓出可编辑的动画小道具。  
完成 05–08：有能力构建有身份一致性的角色、道具和局部特效。  
完成 09–10：能够组织多层像素叙事作品和长期循环壁纸。

**不必把练习做成规定时间的考试。能解释为什么每处像素存在、为什么某层不该动、为什么动画循环自然，才是真正掌握。**

## 证据适用范围与使用限制

1. **原教程的观察不等于所有艺术家的统一标准**：不同画风会在 AA、噪声、轮廓颜色、分辨率、帧率、配色上提出相反选择；把它们做成“默认偏好 + 例外说明”，而不是无条件禁止。
2. **Aseprite 的操作文档用于说明动画与编辑工作流，不代表 PixelWeave 当前已经实现 Aseprite 所有功能**。
3. **部分教程具有付费扩展**：仅列出公开可访问的入门/作者目录，不收录付费教程或素材副本。
4. **数值、评分、练习难度和 PixelWeave 的 Layered DSL 结构** 是本项目自定的工程规范，应随评测反馈迭代。
5. 来源需记录 title / author / URL / accessDate / chapter / claimType。未来可以给每条知识绑定原网址及已通过人工审核的案例，而不是盲目抓取全站文字。
6. 教程可以指导原创技法学习，但不得默认获得教学配图、第三方游戏角色素材或付费资产的再分发许可。
