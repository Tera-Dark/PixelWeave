## 0. 阅读须知

**像素艺术不是“把画面缩小再放大”。** 创作者有意识地控制离散像素、像素簇、边缘节奏、有限色板、负空间和可读性，才构成其独特的视觉语言。关于定义及典型误区，请先读 [Lospec 入门](https://lospec.com/articles/pixel-art-where-to-start/) 和 [Pixel Joint 的系统教程](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)。

本书的目标分为三个层次：

- **人类理解**：读懂专业像素画师为什么这样处理画面；能在工作站上检查和局部修正。
- **模型执行**：让文本 LLM 在固定场景描述、规则和约束下逐层创作，不把未经验证的猜测当知识。
- **系统验证**：PixelWeave 检查尺寸、色板、行宽、帧数、图层数据、运动与循环；主观美感交由人工与视觉评估，并不断复审。

**重要区分**：文中标注的“建议值”（例如 16×16、8–12 色、4–8 帧）是课程练习和初期 LLM 生成的**默认起点**，不是所有像素美术都必须遵守的物理法则。艺术风格允许有意识突破规则。硬性数据约束与审美启发式必须分离。

**资料合规**：所有教学解释、示例任务与规范均为独立整理；只保存外部公开课程的链接和简短摘要，不复制第三方教程的整篇文字、配图、精灵表或付费内容。素材授权与转载条件需另行核对。

**正式推进顺序**：L0 → L1 → L2 → L3/L4 → L5。L3、L4 可并行学习，但 L5 至少完成 L2 + L4。

## 2. 全课程贯穿的 12 条原则

1. **先理解主题和观看尺寸**，明确是游戏道具、角色表情，还是横版背景。
2. **先轮廓后细节**：在 1× 原尺寸与单色模式下必须可读。
3. **优先大形体，再到中型像素簇，最后才是个别高光像素**。
4. **一块像素承担具体功能**：表达形体、材质、光影、运动或情绪；无意义噪点尽量删掉。
5. **控制线条节奏**：避免不规则台阶、轮廓锯齿和不必要的 double pixels。
6. **明暗随体积和光源转折**：谨慎使用围绕整个边缘等距加亮的 pillow shading。
7. **色板要有角色分工**：轮廓/暗部/中间色/主光/极亮点，不能靠无限新增颜色补救形体。
8. **材质靠选择性信息区别**：金属硬反光、玻璃透射边缘、液体宽色块、木材顺纹理。
9. **层与时间线要解耦**：静止的瓶塞不因液体动而重绘跳变。
10. **动画先关键姿态和体积，再局部粒子**：避免全物体无理由漂浮或闪烁。
11. **循环验证最后一帧到第一帧**，不是仅检查逐帧顺序。
12. **每次改动都让艺术判断可追踪**，保存版本和局部差异以便回退。

原则来源综合：[Pixel Joint](https://pixeljoint.com/forum/forum_posts.asp?TID=11299)、[Derek Yu](https://derekyu.com/makegames/pixelart.html)、[Slynyrd 教程目录](https://www.slynyrd.com/pixelblog-catalogue)、[Saint11 教程库](https://saint11.org/blog/pixel-art-tutorials/)；此处为本项目自拟的教学原则，不是引用来源的原文清单。

## 3. 同时服务人类与机器：三层知识加载

不要把整个手册无差别塞给每一次 LLM 请求。使用 **Core → Technique → Case** 的按需加载法：

- **Core（必读）**：画布尺度、风格锚点、轮廓优先、有限色板、结构化资产/JSON 格式、禁止调用生图模型、数据校验。
- **Technique（按任务）**：玻璃、金属、液体、火焰、Idle、走路、雨雾、视差等具体技术章；一次通常只加载 1–3 节。
- **Case（按作品）**：血瓶、提灯、车站、恐怖地牢等案例目标、图层计划、验收表以及经过审核的资产示例。

面向 PixelWeave 的详细编译流程见 [08 LLM 与知识工程](08-LLM-PLAYBOOK.md)；完整评价体系见 [09 质量评测](09-QUALITY-ASSURANCE.md)；阶段练习见 [10 训练计划](10-CURRICULUM.md)。

## 4. 如何学习一章

每章统一要求：

1. **定义**：区分术语、目的与使用范围。
2. **观察**：先在来源教程中找正反例，描述画师的决策，而非抄具体图像。
3. **练习**：在限制画布、色彩和帧数条件下制作原创素材。
4. **评价**：原尺寸辨识、放大像素簇、灰度结构、帧间稳定、循环断点。
5. **复盘**：指出失败属于形体/色板/材质/运动/输出格式哪一层，**只重修对应层**。

入门不要先做 1920×1080 的壁纸。先用 16×16 静态物品证明轮廓表达力，再用 24×24 的瓶子证明材质，再用四帧证明液体与玻璃可以独立运动。

## 5. 人类工作站应提供的检查模式

| 模式 | 目的 | 通过依据 |
| --- | --- | --- |
| 1× 原尺寸预览 | 判断真实观看距离是否可读 | 无需放大能区分物体类型 |
| 黑色剪影 / 灰度 | 测试形体与明度分组 | 亮暗关系清楚，主物体不消失 |
| 调色板视图 | 发现无用途的近似色 | 颜色各自有可解释的角色 |
| 单图层隔离 | 检查层内像素簇、遮挡与边缘 | 图层语义清楚，移除其他层仍能理解作用 |
| Onion skin / 帧差异 | 检查帧间漂移、运动弧和稳定锚点 | 静态结构没有无意义抖动 |
| 首尾跳转 / 循环预览 | 检查循环拼接 | 无明显“跳一下”或突然消失 |
| 参考与版本对比 | 审美迭代 | 能具体说出为何更好，而不是只说“更精致” |

这里的 onion skin、图层、cel、时间线等属于行业常见工作流，参考 [Aseprite 官方入门](https://aseprite.org/docs/basics/) 与 [Onion Skin 文档](https://www.aseprite.org/docs/onion-skinning/)。

## 6. 适用于 PixelWeave 的最小创作路线

**第一件目标作品：一瓶可以逐层编辑的生命药水。**

- 分辨率：建议先 24×24 或 32×32，而不是一上来 64×64。
- 稳定层：瓶塞、瓶身轮廓、玻璃底色与固定阴影。
- 动态层：液面、液内亮区、气泡和偶发闪光。
- 关键挑战：液体仅在玻璃内部变化；瓶塞和外轮廓保持一致；亮点不满屏乱闪。
- 发布门槛：单帧美观、逐帧连贯、循环平顺、导出可重现、JSON 可回读。

详见 [03 道具设计](03-ASSET-DESIGN.md)、[04 动画原理](04-ANIMATION.md) 与 [10 训练计划](10-CURRICULUM.md) 的完整血瓶练习。
