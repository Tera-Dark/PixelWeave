# Pixel world art direction

Create an original place, not a replica of an existing game. Study how cozy farming games use readable tile grids, lively hand-drawn scenery, warm material contrast, and limited color ramps. Never copy game textures, characters, logos, fonts, interface layouts, or recognizable props; do not include extracted assets in the output.

1. Define the product's own story and motifs before drawing: choose a setting, 2–3 materials, foreground/background colors, and a small set of original props relevant to the task.
2. Sketch at native resolution. Use integer-aligned coordinates, cohesive clusters, colored outlines and restrained highlights; avoid scattered one-pixel noise. Keep depth and lighting consistent. Upscale sprites with nearest-neighbor.
3. Give UI a clear hierarchy: natural surfaces for navigation and controls, an unobstructed artwork canvas, readable body text in the user's language, obvious active/focus/disabled/error states. Avoid embedding essential text in images.
4. Make a few loops carry the atmosphere (leaves, light, clouds), rather than animating every control. Stop nonessential animation offscreen and respect reduced motion.
5. Build reusable tokens and original assets; preserve product flows and content attribution. Validate actual desktop and mobile screens, control contrast, keyboard focus, canvas proportions, and unchanged export pixels. Compare visually against the original inspiration for overall feel while avoiding asset-level or layout copying.

When adapting an established project, inspect existing components and constraints first; keep previews and editor stages neutral enough for arbitrary artwork colors. Cite the reference sources in project documentation where appropriate.
